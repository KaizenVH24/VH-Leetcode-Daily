### Leetcode 1320. Minimum Distance to Type a Word Using Two Fingers ( 12th April, 2026 )

---

# Intuition
A brilliant way to frame this problem is to think about "savings." Imagine you only have one finger. To type the entire word, you would have to move that single finger from the first letter to the second, the second to the third, and so on. This gives us a maximum baseline distance. 

When you introduce a second finger, you don't necessarily calculate the cost from scratch. Instead, you calculate how much distance you can *save*. If your first finger is currently on the previous letter (`prev`) and you need to type the current letter (`curr`), the cost is normally `dist(prev, curr)`. But if your second finger is resting on some `other` letter, you can move *that* finger to `curr` instead. This costs `dist(other, curr)`. 

The distance you saved by making this choice is: `dist(prev, curr) - dist(other, curr)`. Our goal is to maximize the total savings across the entire string.

# Approach
1.  **Baseline Distance:** Iterate through the word and sum up the distances between adjacent characters. This is our `total_dist`.
2.  **State Representation (`dp`):** We maintain a DP array of size 27. `dp[other]` will store the maximum savings achieved if the "other" resting finger is currently on the character `other` (0 to 25). 
3.  **The "Free" State:** The 26th index acts as a dummy state representing a finger that hasn't been placed yet. The distance from this unplaced state to any character is `0`, perfectly mimicking the rule that the first placement is free.
4.  **DP Transitions:** For every step from index `1` to `N-1`:
    * Calculate the baseline distance `d` between `prev` and `curr`.
    * Iterate through all 27 possible resting spots for the `other` finger.
    * If we move the `other` finger to `curr`, the finger that was sitting at `prev` becomes the new "resting" finger. 
    * We update our DP state for `prev` by taking the maximum savings: `dp[other] + d - dist(other, curr)`.
5.  **Final Calculation:** Once we finish processing the word, we simply subtract the maximum savings we found (`max(dp)`) from our single-finger `total_dist`.

# Complexity
- Time complexity:
$$O(N)$$
Where $N$ is the length of the string. For each character, we do a constant 27 operations. This makes the time complexity strictly linear, executing in milliseconds.

- Space complexity:
$$O(1)$$
We only use a DP array of size 27, which scales constantly regardless of the input word length.

# Code
```python3 []
class Solution:
    def minimumDistance(self, word: str) -> int:

        def get_dist(a: int, b: int) -> int:
            if a == 26: 
                return 0
            return abs(a // 6 - b // 6) + abs(a % 6 - b % 6)
        
        dp = [0] * 27
        total_dist = 0
        
        for i in range(1, len(word)):
            p = ord(word[i-1]) - 65
            c = ord(word[i]) - 65
            d = get_dist(p, c)
            
            total_dist += d
            new_dp = list(dp)
            
            for other in range(27):
                saving = d - get_dist(other, c)
            
                if dp[other] + saving > new_dp[p]:
                    new_dp[p] = dp[other] + saving
                    
            dp = new_dp
            
        return total_dist - max(dp)
```
