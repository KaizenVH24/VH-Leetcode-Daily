# Intuition
To get as far away from the origin as possible, all of our "free choice" moves (`_`) should be made in the same direction. Specifically, they should be made in whichever direction we are already naturally leaning towards based on the forced `'L'` and `'R'` moves. 

# Approach
Instead of simulating the moves step-by-step, we can solve this mathematically:
1.  Count how many `'L'` and `'R'` moves are explicitly given. 
2.  The baseline distance we are forced to travel is the absolute difference between these two counts: `abs(L_count - R_count)`.
3.  Count the number of free `_` moves.
4.  Add all the free moves to the baseline distance to push the robot as far as possible in the dominant direction.

# Complexity
- Time complexity:
$$O(N)$$
Where $N$ is the length of the string `moves`. Using Python's `.count()` method traverses the string in C, making it highly optimized and strictly linear. We traverse it three times, which simplifies to $O(N)$.

- Space complexity:
$$O(1)$$
We do not allocate any additional scaling memory; we only return a computed integer.

class Solution:
    def furthestDistanceFromOrigin(self, moves: str) -> int:
        l_count = moves.count('L')
        r_count = moves.count('R')
        blank_count = moves.count('_')
        
        return abs(l_count - r_count) + blank_count
