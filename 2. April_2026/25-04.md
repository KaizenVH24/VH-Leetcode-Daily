# Intuition
Trying to calculate the Manhattan distance between random 2D points on a square's boundary sounds like a headache. But there's a neat geometric trick we can exploit here. Since we always have to pick at least $k \ge 4$ points, the maximum possible minimum distance can never exceed the square's `side` length (imagine placing 4 points on the corners; if you shift any of them, some pair gets closer than `side`). 

Because we only care about distances $\le$ `side`, the Manhattan distance between two points on the boundary happens to be exactly the same as the distance walking directly along the perimeter. This means we can completely drop the 2D aspect and "unroll" the square's perimeter into a 1D circular line of length `4 * side`. Once the points are flattened to 1D, this turns into a classic "binary search the answer" problem.

# Approach
1. **Flatten the Perimeter:** Map every 2D coordinate `(x, y)` to a 1D position from `0` to `4 * side`. 
2. **Handle the Wrap-Around:** Since the perimeter is a continuous loop, sort the 1D points and then append a shifted copy of the array (adding `4 * side` to each value). This lets us easily simulate wrapping around the starting point without messy modulo arithmetic.
3. **Binary Search:** Search for the optimal distance `d` in the range `[1, side]`. 
4. **Greedy Validation:** For a given distance `d`, we check if it's possible to pick `k` points. To do this quickly, use a two-pointer approach to precompute an array `nxt` where `nxt[i]` points to the very next available point that is at least `d` distance away. Then, just try starting from each point in the first half of the array, jump `k - 1` times using the `nxt` array, and see if the final point leaves enough room to wrap back to the start. (The `nxt[i] == nxt[i+1]` check is a massive optimization that skips redundant starting points).

# Complexity
- Time complexity:
$$O(N \log N + N \log(\text{side}))$$
Where $N$ is the number of points. Sorting the 1D points takes $O(N \log N)$. The binary search runs $\approx \log(\text{side})$ times. Inside the binary search, building the `nxt` array takes $O(N)$ with two pointers, and validating the jumps takes $O(N)$ thanks to the skip optimization. 

- Space complexity:
$$O(N)$$
We use extra space to store the unrolled 1D arrays `A` and `B`, as well as the `nxt` jump array, all of which scale linearly with the number of input points.

```python3 []
class Solution:
    def maxDistance(self, side: int, points: List[List[int]], k: int) -> int:

        A = []
        # Step 1: Map 2D coordinates to 1D perimeter coordinates
        for x, y in points:
            if y == 0:
                A.append(x)
            elif x == side:
                A.append(side + y)
            elif y == side:
                A.append(3 * side - x)
            else:
                A.append(4 * side - y)
        
        A.sort()
        n = len(A)
        
        # Step 2: Create a doubled array to handle circular wrap-arounds easily
        B = A + [p + 4 * side for p in A]
        
        def isValid(d: int) -> bool:
            nxt = [2 * n] * (2 * n + 1)
            j = 0
            
            for i in range(2 * n):
                while j < 2 * n and B[j] - B[i] < d:
                    j += 1
                nxt[i] = j
            
            limit = 4 * side - d            
            for i in range(n):
                if i < n - 1 and nxt[i] == nxt[i + 1]:
                    continue
                
                curr = i
                for _ in range(k - 1):
                    curr = nxt[curr]
                    
                if curr < 2 * n and B[curr] - B[i] <= limit:
                    return True
                    
            return False

        # Step 3: Binary search for the maximum possible minimum distance
        low = 1
        high = side
        ans = 1
        
        while low <= high:
            mid = (low + high) // 2
            if isValid(mid):
                ans = mid
                low = mid + 1   
            else:
                high = mid - 1    
                
        return ans
