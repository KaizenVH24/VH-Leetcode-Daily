# Intuition
The problem defines a "good" array as a permutation of `base[n] = [1, 2, ..., n - 1, n, n]`. 
This definition tells us two strict rules for an array to be good:
1. If the maximum number in the array is `n`, the array must have exactly `n + 1` elements.
2. The array must contain exactly the numbers from `1` to `n - 1` once, and the number `n` twice.

Because the constraints are very small (`nums.length <= 100`), the most straightforward and readable approach is to just sort the given array and compare it element-by-element to what a perfectly sorted `base[n]` should look like.

# Approach
1. **Determine `n`**: Based on the length of the array, if the array is good, `n` must be `len(nums) - 1`. 
2. **Build Expected Array**: Generate what the valid `base[n]` array should look like. It will be a sequence of numbers from `1` to `n`, with an extra `n` appended at the end.
3. **Compare**: Sort the original `nums` array and check if it is exactly equal to our generated expected array. If they match, it's a good array; otherwise, it's not.

# Complexity
- **Time complexity:** $O(N \log N)$
  Where $N$ is the length of `nums`. Sorting the array takes $O(N \log N)$ time. Creating the expected list and comparing them takes $O(N)$ time. Since $N \le 100$, this will execute essentially instantaneously.
- **Space complexity:** $O(N)$
  We generate a new list `expected` of size $N$, and sorting usually takes $O(N)$ space in Python (Timsort).

class Solution:
    def isGood(self, nums: list[int]) -> bool:
        # Determine what 'n' should be based on the array length
        n = len(nums) - 1
        
        # A valid base array must have at least length 2 (for n=1, base[1]=[1,1])
        if n < 1:
            return False
            
        # Construct the ideal base[n] array
        expected = list(range(1, n + 1)) + [n]
        
        # Check if the sorted input perfectly matches the expected array
        return sorted(nums) == expected
