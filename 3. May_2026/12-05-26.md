# Intuition
To minimize the starting energy, we need to be strategic about the *order* in which we complete the tasks. Every task requires a minimum threshold to start, but only actually consumes a portion of that energy. The difference between what a task requires and what it consumes (`minimum - actual`) acts as a strict "buffer" of energy that must remain *after* the task is completed.

To optimize our energy usage, we should face the most demanding gatekeepers when our energy reserves are at their highest—which is at the very beginning. Therefore, a greedy approach where we tackle tasks with the highest "buffer" requirement first will yield the most optimal sequence.

# Approach
1.  **Define the Sorting Key:** Calculate the buffer energy for each task, which is `minimum - actual`.
2.  **Sort the Tasks:** Sort the `tasks` array in descending order based on this buffer. (If two tasks have the same buffer, their relative order won't negatively impact the overall minimum energy required).
3.  **Simulate and Accumulate:** * Initialize two variables: `initial_energy` (the total energy we are forced to start with) and `current_energy` (our running energy level during the simulation), both starting at `0`.
    * Iterate through the sorted tasks. For each task, check if our `current_energy` is enough to meet the `minimum` requirement.
    * If it's not enough, we calculate the `shortfall` (`minimum - current_energy`). We must artificially "top up" our `initial_energy` and `current_energy` by this shortfall to proceed.
    * Finally, subtract the `actual` energy cost from `current_energy` to complete the task.
4.  **Return:** Once all tasks are processed, `initial_energy` holds the absolute minimum starting energy required.

# Complexity
- Time complexity:
$$O(N \log N)$$
Where $N$ is the number of tasks. Sorting the tasks is the most computationally expensive step. Simulating the tasks requires a single linear scan $O(N)$.

- Space complexity:
$$O(1)$$or$$O(N)$$
If we modify the input array in-place by sorting it, the auxiliary space is strictly $O(1)$ (ignoring the space used by the underlying sorting algorithm). If we return a new sorted array, it takes $O(N)$ space.

class Solution:
    def minimumEffort(self, tasks: list[list[int]]) -> int:
        # Sort tasks descending based on the "buffer" (minimum - actual)
        tasks.sort(key=lambda x: x[1] - x[0], reverse=True)
        
        initial_energy = 0
        current_energy = 0
        
        for actual, minimum in tasks:
            # If we don't have enough energy to start this task, 
            # we need to permanently increase our initial starting energy.
            if current_energy < minimum:
                shortfall = minimum - current_energy
                initial_energy += shortfall
                current_energy += shortfall
                
            # Consume the energy for the task
            current_energy -= actual
            
        return initial_energy
