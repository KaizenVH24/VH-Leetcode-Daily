# Intuition
This problem can be perfectly modeled as a graph traversal. Imagine every index in the array is a node in a graph. From any node `i`, you have up to two directed edges pointing to other nodes: one to `i + arr[i]` (jumping right) and one to `i - arr[i]` (jumping left). 

Our goal is to simply find out if there is a valid path from our starting node (`start`) to any target node that holds the value `0`. Breadth-First Search (BFS) or Depth-First Search (DFS) are ideal for this. 

# Approach
1.  **Initialize a Queue:** We will use Breadth-First Search (BFS). Start by pushing the `start` index into a queue.
2.  **Track Visited Nodes (Optimization Trick):** To prevent infinite loops (jumping back and forth between two identical values), we must keep track of the indices we've already visited. 
    * *Clever Trick:* Since the problem states all integers in the array are non-negative, we can mark an index as "visited" by flipping its value to negative (`arr[i] = -arr[i]`). This saves us from allocating an entirely separate $O(N)$ `visited` set!
3.  **Traverse the Graph:**
    * Pop the current index from the queue.
    * If the value at this index is `0`, we've found our target! Return `True`.
    * If the value is less than `0`, we've already visited it, so skip it.
    * Calculate the two possible next indices: `left = curr - arr[curr]` and `right = curr + arr[curr]`.
    * If these new indices are within the bounds of the array, add them to the queue.
    * Mark the current index as visited by negating its value.
4.  **Return False:** If the queue runs dry and we never hit a `0`, it means all reachable nodes have been explored and no `0` exists in that component of the graph. Return `False`.

# Complexity
- **Time complexity:** $\mathcal{O}(N)$
  Where $N$ is the length of the array. In the worst-case scenario, we might have to visit every single index in the array. Since we mark nodes as visited, we process each index exactly once.
- **Space complexity:** $\mathcal{O}(N)$
  Although we optimized away the `visited` set by modifying the input array in-place, the BFS queue itself can grow to hold up to $N$ elements in the worst case.

from collections import deque

class Solution:
    def canReach(self, arr: list[int], start: int) -> bool:
        queue = deque([start])
        n = len(arr)
        
        while queue:
            curr = queue.popleft()
            
            # Target found
            if arr[curr] == 0:
                return True
                
            # If we've already visited this index, skip it
            if arr[curr] < 0:
                continue
                
            # Calculate the left and right jump targets
            jump = arr[curr]
            left = curr - jump
            right = curr + jump
            
            # Add valid targets to the queue
            if left >= 0:
                queue.append(left)
            if right < n:
                queue.append(right)
                
            # Mark the current index as visited by making it negative
            arr[curr] = -arr[curr]
            
        return False
