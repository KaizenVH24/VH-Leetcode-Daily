# Intuition
The problem asks us to find the minimum element in a sorted array that has been rotated, and we must do it in $O(\log n)$ time. This time complexity constraint is a massive hint: we need to use **Binary Search**.

If you look closely at a rotated sorted array (e.g., `[4, 5, 6, 7, 0, 1, 2]`), it is essentially composed of two strictly increasing subarrays. The minimum element is the "inflection point" where the first subarray drops down to the second subarray. 

To find this point using binary search, we compare the middle element (`nums[mid]`) with the rightmost element (`nums[right]`). 
* If `nums[mid] > nums[right]`, we know the array is "out of order" in the right half, meaning the inflection point (and thus the minimum) **must** be to the right of `mid`.
* If `nums[mid] < nums[right]`, the right half is perfectly sorted in ascending order. This means the minimum cannot be to the right of `mid`; it must be at `mid` itself or somewhere to its left.

# Approach
1.  **Initialize Pointers:** Set `left = 0` and `right = len(nums) - 1`.
2.  **Binary Search Loop:** Run a `while left < right` loop. (Notice we don't use `<=` because we are not searching for a specific target value; we are narrowing down a boundary).
3.  **Calculate Midpoint:** Find `mid = left + (right - left) // 2`.
4.  **Compare and Shift:**
    * If `nums[mid] > nums[right]`, the minimum is strictly to the right. Set `left = mid + 1`.
    * Otherwise (`nums[mid] <= nums[right]`), the minimum is at `mid` or to the left. Set `right = mid`.
5.  **Return:** When `left == right`, the search space has shrunk to a single element, which is guaranteed to be the minimum. Return `nums[left]`.

# Complexity
- **Time complexity:** $\mathcal{O}(\log n)$
  In each step of the `while` loop, we cut the search space exactly in half. This yields a logarithmic time complexity, satisfying the problem's strict constraint.
  
- **Space complexity:** $\mathcal{O}(1)$
  We only use a few integer variables (`left`, `right`, `mid`) to keep track of indices, requiring constant extra memory.

# Code
```python3 []
class Solution:
    def findMin(self, nums: list[int]) -> int:
        left, right = 0, len(nums) - 1
        
        # If the array is strictly increasing (0 rotations or n rotations), 
        # the first element is already the minimum.
        if nums[left] < nums[right]:
            return nums[left]
            
        while left < right:
            mid = left + (right - left) // 2
            
            # If mid element is greater than the rightmost element,
            # the minimum must be in the right half (excluding mid).
            if nums[mid] > nums[right]:
                left = mid + 1
            # Otherwise, the right half is sorted, 
            # so the minimum is in the left half (including mid).
            else:
                right = mid
                
        # When left == right, we have found the minimum element
        return nums[left]
