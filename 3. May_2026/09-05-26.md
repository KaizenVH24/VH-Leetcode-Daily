# Intuition
The problem requires us to rotate the layers of a 2D matrix counter-clockwise by `k` steps. Operating directly on the 2D coordinates for a cyclic shift is messy and prone to off-by-one errors. 

However, if we imagine "peeling" each layer off the grid and unrolling it into a flat 1D array in clockwise order, a counter-clockwise rotation becomes trivial. A counter-clockwise move on the grid perfectly corresponds to shifting the elements of our unrolled 1D array to the *left*. Because `k` can be massive (up to $10^9$), we can calculate the effective shifts using modulo arithmetic (`k % length`). Once the 1D array is shifted, we simply wrap it back onto the grid in the exact same clockwise path.

# Approach
1.  **Identify Layers:** The number of concentric layers in an $m \times n$ matrix is always $\min(m, n) // 2$.
2.  **Define Boundaries:** For each layer `i`, define its bounds:
    * `top = i`
    * `bottom = m - 1 - i`
    * `left = i`
    * `right = n - 1 - i`
3.  **Extract:** Traverse the perimeter of the current layer in a clockwise direction (Top row $\rightarrow$ Right column $\rightarrow$ Bottom row $\rightarrow$ Left column) and append the elements to a 1D list `arr`.
4.  **Rotate:** Calculate the effective number of rotations needed: `shifts = k % len(arr)`. Shift the list left by this amount using Python slicing: `arr[shifts:] + arr[:shifts]`.
5.  **Write Back:** Traverse the same clockwise perimeter on the grid and overwrite the cells sequentially with the values from our newly rotated 1D list.

# Complexity
- Time complexity:
$$O(m \times n)$$
Every element in the $m \times n$ grid is extracted exactly once, shifted exactly once, and written back exactly once. The time it takes is directly proportional to the number of elements in the grid. `k` does not affect the time complexity due to the modulo operation.

- Space complexity:
$$O(m + n)$$
We process one layer at a time. The memory overhead comes from storing the 1D array of the current layer. The largest layer is the outermost one, which has a perimeter of roughly $2m + 2n$. Thus, the auxiliary space strictly scales with $O(m + n)$.

class Solution:
    def rotateGrid(self, grid: list[list[int]], k: int) -> list[list[int]]:
        m, n = len(grid), len(grid[0])
        num_layers = min(m, n) // 2
        
        for layer in range(num_layers):
            top, bottom = layer, m - 1 - layer
            left, right = layer, n - 1 - layer
            
            arr = []
            
            # 1. Extract 1D array in Clockwise order
            # Top row
            for c in range(left, right + 1):
                arr.append(grid[top][c])
            # Right column
            for r in range(top + 1, bottom + 1):
                arr.append(grid[r][right])
            # Bottom row
            for c in range(right - 1, left - 1, -1):
                arr.append(grid[bottom][c])
            # Left column
            for r in range(bottom - 1, top, -1):
                arr.append(grid[r][left])
                
            # 2. Shift array left for Counter-Clockwise rotation
            length = len(arr)
            shifts = k % length
            arr = arr[shifts:] + arr[:shifts]
            
            # 3. Write the rotated values back to the grid
            idx = 0
            # Top row
            for c in range(left, right + 1):
                grid[top][c] = arr[idx]
                idx += 1
            # Right column
            for r in range(top + 1, bottom + 1):
                grid[r][right] = arr[idx]
                idx += 1
            # Bottom row
            for c in range(right - 1, left - 1, -1):
                grid[bottom][c] = arr[idx]
                idx += 1
            # Left column
            for r in range(bottom - 1, top, -1):
                grid[r][left] = arr[idx]
                idx += 1
                
        return grid
