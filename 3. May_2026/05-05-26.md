# Intuition
Rotating a linked list to the right by `k` places essentially means taking the last `k` nodes and moving them to the front. 

Since `k` can be massively larger than the length of the list (up to 2 * 10^9), simulating the rotation step-by-step would result in a Time Limit Exceeded (TLE) error. However, rotating a list of length `n` by `n` steps brings it right back to its original state. Therefore, we only actually need to perform `k % n` rotations.

The most elegant way to handle this is to temporarily connect the tail of the list to the head, creating a circular linked list. Then, we just calculate where the "new" tail should be, walk to it, and break the circle.

# Approach
1.  **Handle Edge Cases:** If the list is empty (`head` is `None`), has only one node (`head.next` is `None`), or `k == 0`, no rotation is needed. Return the `head` as is.
2.  **Find the Length and Tail:** Traverse the list to count the total number of nodes (`n`) and locate the very last node (`tail`).
3.  **Optimize `k`:** Update `k` to be `k % n`. If the new `k` is `0`, the list remains unchanged, so return the `head`.
4.  **Create a Cycle:** Link the `tail.next` to the `head` to form a circular linked list.
5.  **Find the New Head and Tail:**
    *   The new tail will be located exactly `n - k - 1` steps from the original head.
    *   We traverse to this new tail node.
    *   The new head will be the node immediately following the new tail (`new_tail.next`).
6.  **Break the Cycle:** Set `new_tail.next = None` to sever the loop and return the `new_head`.

# Complexity
- **Time complexity:**
  `O(n)`
  We traverse the list once to find the length (taking `n` steps), and then we traverse it a second time to find the new tail (taking `n - k` steps). In the worst case, this is `O(2n)`, which simplifies to strictly linear `O(n)` time.

- **Space complexity:**
  `O(1)`
  We only allocate a few pointers (`tail`, `new_tail`, `new_head`, `length`) to keep track of our position. No additional data structures are created, so memory scaling is perfectly constant.

# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        # Step 1: Handle edge cases
        if not head or not head.next or k == 0:
            return head
            
        # Step 2: Find the length of the list and the last node
        length = 1
        tail = head
        while tail.next:
            tail = tail.next
            length += 1
            
        # Step 3: Calculate effective rotations
        k = k % length
        if k == 0:
            return head
            
        # Step 4: Form a circular linked list
        tail.next = head
        
        # Step 5: Traverse to the new tail (length - k - 1 steps from head)
        steps_to_new_tail = length - k
        new_tail = head
        for _ in range(steps_to_new_tail - 1):
            new_tail = new_tail.next
            
        # The new head is the next node
        new_head = new_tail.next
        
        # Step 6: Break the circle
        new_tail.next = None
        
        return new_head
