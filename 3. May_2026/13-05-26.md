# Intuition
The problem asks us to find a target sum $T$ such that the total number of operations to make every pair $(nums[i], nums[n-1-i])$ sum up to $T$ is minimized. 
Because the limit can be large, checking every possible target sum $T$ (from $2$ to $2 \times limit$) against every pair would result in an $O(N \times L)$ time complexity, leading to a Time Limit Exceeded (TLE) error.

Instead, let's analyze how the required moves change for a single pair $(a, b)$ based on the chosen target sum $T$. Assuming $a \le b$:
*   **0 moves:** If $T == a + b$. We don't need to change anything.
*   **1 move:** We can change just one number.
    *   If we change $b$ to $1$ (the minimum possible), the sum becomes $a + 1$.
    *   If we change $a$ to $limit$ (the maximum possible), the sum becomes $b + limit$.
    *   Thus, we need exactly $1$ move if $T$ falls in the range $[a + 1, b + limit]$, except for $T = a + b$.
*   **2 moves:** For any target sum $T$ outside the above ranges ($T < a + 1$ or $T > b + limit$), we must change both numbers to hit the target.

This structure implies that for each pair, the cost function over the domain of $T$ changes at specific boundary points. This is a classic setup for the **Difference Array** (or Line Sweep) technique, which allows us to apply range updates in $O(1)$ time.

# Approach
1.  **Initialize Difference Array:** Create a `delta` array of size `2 * limit + 2` to store the changes in moves. We use size `2 * limit + 2` to safely handle indices up to `2 * limit + 1`.
2.  **Populate Delta:** Loop through the first half of the array. For each pair $(a, b)$ where $a = \min(nums[i], nums[n-1-i])$ and $b = \max(nums[i], nums[n-1-i])$:
    *   The baseline cost for any $T \ge 2$ is $2$ moves. Update: `delta[2] += 2`.
    *   Starting at $T = a + 1$, the cost drops to $1$ move. Update: `delta[a + 1] -= 1`.
    *   Exactly at $T = a + b$, the cost drops to $0$ moves. Update: `delta[a + b] -= 1`.
    *   Right after $T = a + b$, at $T = a + b + 1$, the cost goes back up to $1$ move. Update: `delta[a + b + 1] += 1`.
    *   Right after $T = b + limit$, at $T = b + limit + 1$, the cost goes back up to $2$ moves. Update: `delta[b + limit + 1] += 1`.
3.  **Prefix Sum:** Iterate through the `delta` array from $2$ to $2 \times limit$. Keep a running total (prefix sum) to determine the exact number of moves needed for each specific target sum $T$. 
4.  **Find Minimum:** Track and return the minimum running total observed.

# Complexity
- **Time complexity:** $\mathcal{O}(N + L)$
  Where $N$ is the length of `nums` and $L$ is the `limit`. We iterate through $N/2$ pairs to populate the difference array in $\mathcal{O}(N)$ time. Then, we do a linear scan over the difference array of size $2L$ to calculate the prefix sum, taking $\mathcal{O}(L)$ time.
  
- **Space complexity:** $\mathcal{O}(L)$
  We allocate a `delta` array of size $2 \times limit + 2$.

```python3 []
class Solution:
    def minMoves(self, nums: list[int], limit: int) -> int:
        n = len(nums)
        # Difference array to record step changes in the cost
        # Size up to 2 * limit + 2 to safely handle index limits
        delta = [0] * (2 * limit + 2)
        
        for i in range(n // 2):
            a = min(nums[i], nums[n - 1 - i])
            b = max(nums[i], nums[n - 1 - i])
            
            # Boundary points for cost changes
            delta[2] += 2
            delta[a + 1] -= 1
            delta[a + b] -= 1
            delta[a + b + 1] += 1
            delta[b + limit + 1] += 1
            
        current_moves = 0
        min_moves = float('inf')
        
        # Calculate prefix sum to find the cost at each target T
        for target in range(2, 2 * limit + 1):
            current_moves += delta[target]
            if current_moves < min_moves:
                min_moves = current_moves
                
        return min_moves
